# Pricetitute — роадмап

Правила и функционал — в [SPEC.md](./SPEC.md). Здесь только план работ:
что делаем, в каком порядке и что считается готовым.

## Порядок и зависимости

```
Э0 Каркас
 └─ Э1 Аккаунты ──┐
 └─ Э2 Вопросы ───┴─ Э3 Игровой движок ─ Э4 Реалтайм ─ Э5 Интерфейс игры
                                                        ├─ Э6 Общая комната
                                                        └─ Э7 Приватные комнаты
                                                             └─ Э8 Полировка и деплой
```

Э1 и Э2 независимы, делаются параллельно. Э3 и Э5 идут внахлёст: как только
машина состояний отдаёт события, интерфейс собирается против реального контракта,
а не против макета.

- [x] `create-next-app`: Next.js 16 (App Router) + TypeScript + Tailwind 4
- [x] ESLint + Prettier, строгий `tsconfig` (`noUncheckedIndexedAccess` и др.)
- [x] `docker-compose.yml` с PostgreSQL 17 для локальной разработки
- [x] Prisma 7: схема, `prisma.config.ts`, адаптер `@prisma/adapter-pg`,
      миграция `init`, `.env.example`
- [x] Кастомный сервер `server.ts`: Next + Socket.IO в одном процессе,
      upgrade-запросы разведены между Socket.IO и Next HMR
- [x] Базовый layout, тёмная тема, палитра, кириллический сабсет шрифтов
- [x] `.gitignore`, README, первый коммит

**Готово:** `npm run dev` поднимает приложение и сокет-сервер на одном порту,
`prisma migrate dev` накатывает схему, `npm run build`, `lint` и `typecheck`
проходят чисто.

## Этап 1 — Аккаунты

- [x] Схема `User`: `login`, `passwordHash`, `nickname`, `avatarId`, `adultConfirmedAt`, `createdAt` — заведена в этапе 0 вместе с первой миграцией
- [x] Хеширование паролей (argon2), сессия — подписанный JWT в httpOnly cookie
- [x] Регистрация: логин 3–20 символов, пароль от 8, ник отдельным полем, галочка 18+
- [x] Вход, выход, защита роутов через `proxy.ts`
- [x] **Пул из 30 аватаров** — 8 зверей (кот, пёс, ёж, ящерка, лиса, лягушка,
      сова, енот) в цветовых вариантах, часть с кепкой, очками или бабочкой.
      Рисуются инлайновым SVG, файлов на диске нет. Выдача случайного при
      регистрации.
- [x] Страница профиля: смена ника, перевыбор аватара из пула
- [x] Валидация форм и человеческие тексты ошибок

**Готово:** регистрация, вход, выход и смена аватара работают; логин уникален
без учёта регистра; неверный пароль и несуществующий логин дают одинаковый
текст ошибки; введённые значения переживают неудачную отправку формы.
Восстановления пароля нет — это решённый компромисс, не задача.

## Этап 2 — Пул вопросов

- [x] Схема `Question`: `text`, `category`, `adult`, `active`
- [x] Схема истории показов `RoomQuestionQueue`: очередь и список уже выданных,
      отдельной строкой на комнату (`global` — общая, иначе id приватной)
- [x] **Стартовый пул на 500 вопросов**: ровно 250 бытовых, 150 социально
      рискованных, 100 с флагом 18+. Разложен по шести файлам примерно по 100,
      сгруппирован по тону, чтобы вычитывать партиями
- [x] Seed-скрипт: проверяет пул на повторы, заливает через `createMany`
      со `skipDuplicates`, повторный запуск безопасен
- [x] Логика очереди: перемешивание, выдача с головы, возврат сгоревшего вопроса
      в нижнюю треть на случайную позицию, повторное перемешивание при исчерпании
- [x] Тесты на очередь — 11 штук, на детерминированном генераторе

**Готово:** `loadQuestionQueue` поднимает очередь комнаты с учётом настройки 18+,
`saveQuestionQueue` переживает перезапуск сервера, показанные вопросы не
возвращаются в очередь, пул без 18+ отдаёт 400 вопросов из 500.

## Этап 3 — Игровой движок (сервер)

Ядро проекта. Пишется отдельно от транспорта, чтобы покрывалось тестами.

- [x] Модель состояния комнаты в памяти: игроки, круг ходов, текущая фаза, дедлайн
- [x] Машина состояний: `READY 20с → HOST_ANSWER 15с → BETTING 5мин → REVEAL 30с`
- [x] Серверные таймеры вынесены в `RoomRunner` — единственное место с
      `setTimeout`; наружу отдаётся абсолютный `deadline` (unix ms)
- [x] Переход хода по кругу, пропуск отвалившихся, сгорание вопроса
- [x] Приём ставок: только один раз, изменение запрещено, досрочное закрытие
      фазы когда поставили все
- [x] **Подсчёт очков**: логарифмическая близость, спец-случаи «Бесплатно» и
      «Ни за какие деньги», ничьи, ведущий без очков
- [x] Пауза комнаты при <2 активных игроков
- [x] Персист в БД: `Round`, `RoundBet`, `Score` одной транзакцией
- [x] 45 юнит-тестов: формула близости, все спец-случаи с ∞ и 0, ничьи, каждый
      переход фаз, сгорание на обоих таймерах, работа таймеров раннера

**Готово:** движок прогоняет полный цикл раундов в тестах без сети и UI, а на
живой базе раунд доигрывается до записи очков. Движок ничего не знает про
сокеты и Prisma: время приходит параметром, вопросы — через `QuestionSource`
(`QuestionQueue` подходит под него без адаптера), запись в базу делает
подписчик события `round_resolved`.

## Этап 4 — Реалтайм-слой

- [x] Аутентификация сокета по той же cookie, что и у страниц; без сессии
      подключение отклоняется
- [x] Комнаты Socket.IO, подписка/отписка, учёт нескольких вкладок одного
      игрока: из-за стола он выходит, только когда закрыл последнюю
- [x] Контракт событий — [src/shared/protocol.ts](../../../shared/protocol.ts).
      **Сделано не так, как планировалось:** вместо россыпи `round:phase`,
      `round:question`, `bet:placed`, `player:joined` сервер шлёт один
      `room:state` с полным снимком. Причина — снимок всё равно нужен для
      реконнекта, а две параллельные схемы обновления неизбежно разъезжаются.
      Отдельными событиями остались только чат и история чата
- [x] Реконнект: тот же `room:state` восстанавливает всё, отдельного пути нет
- [x] Рейт-лимиты: 20 действий за 5 секунд и 5 сообщений за 10 секунд на игрока;
      любая ставка проверяется на сервере через `parseBet`
- [x] Ответ ведущего и чужие ставки не покидают сервер до фазы вскрышки, а
      текст вопроса в фазе READY уходит только ведущему — состояние собирается
      персонально под каждый сокет

**Готово:** `npm run smoke:sockets` прогоняет два клиента через полный раунд —
30 проверок, включая скрытность вопроса и ответа, отказы чужим действиям,
лимиты чата, реконнект и отказ безсессионному клиенту. Два браузера ждут
интерфейса из этапа 5.

## Этап 5 — Интерфейс игры

Оформление: красно-розово-белое, светлая тема. Название игры в интерфейсе
всегда русское — **Платитутка**; латинское Pricetitute осталось только именем
репозитория.

- [x] Экран комнаты: вопрос, индикатор фазы, таймер со шкалой, список игроков
      со статусами («думает» / «поставил» / «ведущий»)
- [x] Экран ведущего: кнопка «Прочитал» с обратным отсчётом 20с, затем ввод
      своей суммы за 15с
- [x] **Ввод ставки**: числовое поле с разделением разрядов, пресеты
      (1к / 10к / 100к / 1млн), кнопки «Бесплатно» и «Ни за какие деньги»
- [x] Экран вскрытия: ответ ведущего и все ставки разом, победитель золотом,
      шкала точности и промах словами («мимо в 1.5 раза»)
- [x] Таблица очков комнаты в боковой колонке
- [x] Чат: история 100 сообщений, лимит 300 символов
- [x] Адаптив: две колонки на десктопе, одна на телефоне
- [x] Состояния ожидания: «ждём второго игрока», «ведущий читает вопрос»,
      «вопросы кончились», обрыв связи

**Готово:** раунды играются руками с десктопа и с телефона. Проверено на живой
комнате с ботом-напарником: смена ведущего по кругу, скрытый вопрос, ставка,
вскрышка с числовым ответом и с отказом, обновление страницы посреди раунда.

Таймеры фаз считаются от серверного времени: в снимке приходят абсолютный
дедлайн и время сервера, клиентские часы в расчёте не участвуют.

## Этап 6 — Общая комната

- [x] Автоматический вход в единственную общую комнату (сделано на этапе 4)
- [x] Круг ходов в порядке подключения, новый игрок в конец круга
- [x] Начисление очков в глобальный рейтинг
- [x] Страница рейтинга `/leaderboard`: за всё время и за текущую неделю,
      топ-100 плюс своя строка отдельно, если в топ не попал
- [x] Поведение при наплыве: 7 тестов на круг ходов с текучкой состава и
      сокетная проверка на дюжине живых клиентов

**Готово:** очки попадают в обе таблицы. За всё время счёт берётся из
накопленной `Score`, за неделю пересчитывается по раундам — так не нужен
отдельный счётчик на каждый период, а старые раунды из недельного зачёта
выпадают сами.

При равных очках выше тот, кому хватило меньше раундов: иначе рейтинг
превращался бы в таблицу усидчивости, где достаточно просто дольше сидеть
в комнате.

## Этап 7 — Приватные комнаты

- [x] Создание комнаты на `/rooms/new`, код из шести символов без похожих
      букв, страница `/r/<code>`
- [x] Инвайт-ссылка с кнопкой копирования; вход только по аккаунту, гостя
      уводит на вход и возвращает ровно в ту же комнату
- [x] Настройки хоста при создании: длительность фазы ставок, 18+ вкл/выкл,
      условие конца партии (N раундов / до N очков / бесконечно)
- [x] Права хоста: выгнать игрока, начать новую партию после финала
- [x] Счёт изолирован от глобального рейтинга — лежит под ключом комнаты
- [x] Финальный экран: победитель, итоговая таблица, кнопка «Сыграть ещё раз»
- [x] Удаление комнаты через 30 минут после ухода последнего игрока вместе с
      её очередью вопросов и счётом; ссылка умирает вместе с комнатой

**Готово:** компания заходит по одной ссылке и играет партию до конца. Проверено
руками с ботом-напарником: создание с настройками, вход по коду, укороченная
фаза ставок, финальный экран, перезапуск партии с обнулением счёта, выгон
игрока. Плюс 14 юнит-тестов на правила партии и проверка жизненного цикла
комнаты на живой базе.

Выгон игрока не ограничивается удалением из круга: сервер рвёт его соединение
и объясняет причину. Иначе выгнанный остался бы в комнате призраком — видел бы
игру, но не мог в ней участвовать.

Добавлена кнопка «Сыграть ещё раз», которой не было в плане: без неё комната
после финала превращалась в тупик, из которого можно только уйти.

## Этап 7.5 — Forever alone

Играть одному, пока не подтянулись живые.

- [x] Кнопка «Forever alone» в своей комнате: видна только хозяину и только
      пока он один. Появился живой игрок — кнопка пропала
- [x] По нажатию садятся 10 ботов из состава на 50 имён в духе игровых ников
      нулевых: `---===ЛАЗЕРНЫЙ/\ВИТАЛЯ===---`, `TURBO_KILLER_SASHA`
- [x] Аватары ботов — роботы в шляпах и очках, отдельный пул: игрок себе
      такого не выберет, робот в комнате всегда бот
- [x] Боты играют сами: ведут раунд, называют случайную сумму, ставят
      наугад. Суммы берутся по логарифмической шкале, так что попадаются и
      сотни, и миллионы, а изредка бот отказывается или соглашается даром
- [x] Болтают в чат мемами: каждый со своим интервалом 30–190 секунд, но
      комната молчит 40 секунд после любой ботовской реплики — иначе десять
      ботов забивают чат
- [x] Зашёл живой игрок — каждый бот прощается в стиле своего ника и уходит

**Готово:** проверено вживую — боты пришли, отыграли раунд с нормальным
разбросом ставок, поболтали, а на появление второго человека попрощались
(«ПОСЛЕДНЕЕ ДЕРЕВО СРУБЛЕНО. ЮРА СВОБОДЕН») и вышли.

Боты — настоящие записи в таблице игроков, иначе не сохранить раунд: ставка
ссылается на игрока. Вход под ботом закрыт отдельной проверкой, в общую
комнату они не заходят, поэтому в глобальный рейтинг не попадают — и с тех пор
запросы рейтинга отсекают их ещё и напрямую по флагу, чтобы это не зависело от
будущих правок.

## Этап 8 — Полировка и запуск

- [x] Лендинг с правилами в четыре шага и возрастной плашкой
- [x] Экраны ошибок: `not-found`, `error` на сегмент, `global-error` на случай
      падения самого макета; обрыв связи показывается прямо в комнате
- [x] Вскрышка проявляется по строчкам, с уважением к `prefers-reduced-motion`.
      Звуков нет — по плану они и не блокировали запуск
- [x] Логирование и отлов ошибок: процесс переживает необработанные исключения
      и промисы, по SIGTERM гасит таймеры комнат и ботов и закрывается сам
- [x] Артефакты выкладки: Dockerfile, `.dockerignore`,
      [docs/DEPLOY.md](../../../../docs/DEPLOY.md) с переменными, порядком миграций, бэкапом и
      честным описанием ограничения в один процесс
- [x] Проверка под нагрузкой: 25 живых клиентов, три раунда, одновременный
      уход половины состава — круг ходов цел

Образ собран и проверен в работе: контейнер отдал страницы, поднял сокеты и
прогнал через себя раунды со смоук-тестом.

**Готово к запуску, но не запущено.** Собрать образ и накатить миграции можно
хоть сейчас, а вот выбрать хостинг и завести на нём базу — это уже к тебе:
нужны твои доступы. Скажи куда, и доведу.

**Что важно знать про эксплуатацию.** Игровое состояние комнат живёт в памяти
процесса, поэтому масштабировать вширь нельзя: два инстанса разведут игроков по
двум независимым общим комнатам. Перезапуск обрывает идущие раунды — очередь
вопросов и счёт его переживают, текущий раунд нет. Всё это расписано в
[docs/DEPLOY.md](../../../../docs/DEPLOY.md).

## Отложено осознанно

Из раздела компромиссов спеки — делаем, только если упрёмся:

- админка вопросов и пользовательские предложения вопросов;
- блокировка чата в фазе ставок против сговора в общей комнате;
- капча или обязательный email против мультиаккаунтов в рейтинге;
- параллельные столы в общей комнате, если ожидание своего хода станет долгим.
