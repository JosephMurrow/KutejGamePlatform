# Турбо-шахматы — правила в коде

Как правила работают в коде. Постановка — в [BACKLOG.md](BACKLOG.md), режимы —
в [MODES.md](MODES.md), порядок работ — в [PLAN.md](PLAN.md).

Всё, что здесь описано, живёт в `src/games/turbochess/engine/` и не знает ни
про сеть, ни про базу, ни про экран: время приходит снаружи отдельным
сообщением «флаг упал». Код без серверных зависимостей — тот же движок
подскажет ходы и в браузере.

## 1. Свой движок, а не библиотека

`chess.js` не умеет ничего из того, что нужно режимам: доску не 8×8, четырёх
игроков, свои фигуры, резерв, отмену чужого хода ([BACKLOG.md](BACKLOG.md) B1).
Поэтому правила свои. Библиотека в игре упоминается ровно в одном месте — в
тесте, который сверяет с ней свой генератор (раздел 10).

| Файл          | Что в нём                                                  |
| ------------- | ---------------------------------------------------------- |
| `geometry.ts` | Размер доски, номера и имена клеток, шаг по вектору        |
| `pieces.ts`   | Виды фигур и таблица их ходов                              |
| `position.ts` | Позиция и начальная расстановка                            |
| `moves.ts`    | Генерация и законность ходов, запись, повторения, материал |
| `game.ts`     | Партия: фасад, повторяющий шахматный `ChessGame`           |
| `outcome.ts`  | Чем кончилась партия и как это назвать человеку            |
| `clock.ts`    | Лимит на ход — копия шахматных часов                       |
| `fen.ts`      | Позиция из FEN — только для тестов                         |

## 2. Доска и стороны

Внутри клетка — число `y * width + x`, наружу — строка `e4`: так клетки уже
ходят по проводу у шахмат. Размер доски — параметр: 8×8 у всех режимов, 16×16
у королевской битвы. Потолок — 26 вертикалей: букву вертикали библиотека доски
берёт из кода символа.

Сторона — номер места за столом: у двоих белые — 0, чёрные — 1. У каждой
стороны своё направление пешек, и из него следует всё пешечное: откуда
двойной шаг, куда бьют, где превращение. Для королевской битвы сторон будет
четыре, по одной на край доски, — генератор ходов при этом не меняется.

## 3. Позиция

Неизменяемый объект: доска, очередь, права рокировки, поле взятия на проходе,
счётчик полуходов без взятий и ходов пешкой и то, что забрала каждая сторона.
Ход даёт новую позицию, старая остаётся, какой была: на этом держится ход
назад, перебор ботов и запись партии.

FEN как формат позиции не годится — он не описывает ни доску 16×16, ни
четыре стороны, ни резерв. Он остался только в тестах: справочные позиции
записаны им.

Права рокировки хранятся клетками — какой король, какая ладья, куда встают, —
а не буквами `KQkq`. Так рокировка не привязана ни к углам доски 8×8, ни к
двум сторонам.

## 4. Ходы

**Как ходит фигура, задано таблицей:** прыжки на один вектор (конь, король) и
лучи до первой преграды (слон, ладья, ферзь). Пешки в таблице нет — у неё пять
разных правил, и все зависят от стороны.

**Законность — честная:** ход делается на копии доски, и если после него свой
король под боем, хода нет. Поэтому связки, вскрытые шахи и взятие на проходе,
вскрывающее горизонталь на своего короля, ловятся без отдельных правил.

**Рокировка — одним общим правилом:** между королём, ладьёй и местами, куда
они встают, пусто (кроме них самих), король не под шахом и не проходит битых
полей. Право гаснет, когда сходил король — тогда все права его стороны, — или
когда ладья ушла со своего места или её там забрали.

**Приём хода — как у шахмат.** На проводе ход — `{ from, to, promotion? }` и
номер полухода. Отказы внятные, а не исключение:

| Причина          | Когда                                        |
| ---------------- | -------------------------------------------- |
| `gameOver`       | партия уже кончилась                         |
| `stalePly`       | клиент считает ход другим по счёту           |
| `needsPromotion` | пешка доходит до края, а фигура не названа   |
| `illegal`        | хода нет, или клетки кривые                  |
| `notYourTurn`    | ходит соперник — решает комната, а не движок |

Рокировка принимается двумя способами — король на две клетки и король на свою
ладью. Фигура превращения при обычном ходе молча пропускается, как у
библиотеки шахмат.

## 5. Запись партии

Обычная запись: `e4`, `Nbd2`, `exd6`, `e8=Q+`, `O-O-O#`. Уточнение, какая из
двух фигур пошла, ставится только тогда, когда вторая тоже может туда законно
пойти: сначала вертикалью, потом горизонталью, потом полем целиком. Запись
сверена с `chess.js` на каждом узле (раздел 10).

## 6. Чем кончается партия

Способы те же, что у шахмат, и у каждого своя причина. Результат — номер
стороны-победителя или ничья.

| Причина              | Что случилось                                 |
| -------------------- | --------------------------------------------- |
| `checkmate`          | мат                                           |
| `stalemate`          | пат                                           |
| `resign`             | сдался                                        |
| `flag`               | не успел с ходом                              |
| `flagVsInsufficient` | флаг, но сопернику нечем матовать — **ничья** |
| `insufficient`       | ни одной стороне не хватает материала         |
| `threefold`          | позиция повторилась трижды — по заявке        |
| `fivefold`           | позиция повторилась пять раз — сама           |
| `fiftyMoves`         | пятьдесят ходов без взятий — по заявке        |
| `seventyFiveMoves`   | семьдесят пять ходов — сама                   |
| `agreement`          | согласились на ничью                          |
| `abandoned`          | ушёл и не вернулся                            |
| `aborted`            | разошлись до первого хода                     |
| `tooLong`            | предохранитель: партия затянулась             |

**Недостаточный материал** — как у `chess.js`: король против короля, король
с одной лёгкой фигурой против короля, короли со слонами на полях одного
цвета. Два коня недостаточными не считаются — мат ими возможен.

**Флаг при недостаточном материале у соперника — ничья.** Матовать нечем с
голым королём, с одной лёгкой фигурой и любым числом слонов на полях одного
цвета.

**Все выходы — через одну дверь**, и первым делом она проверяет, что партия
ещё идёт: сдача, пришедшая одновременно с матом, не посчитается дважды.

Свои окончания режимов — «все фигуры сняты», «сброшена бомба», «король дошёл
до трона» — добавятся на их этапах.

## 7. Повторения и счётчик ходов

Играем по ФИДЕ. Позиция считается той же, если та же сторона ходит, те же
фигуры стоят на тех же полях, те же права рокировки и та же возможность взять
на проходе. Поле взятия на проходе входит в позицию, только если такое взятие
законно: пешка, прошедшая на два поля мимо пустоты, позицию не меняет.

| Основание             | Что происходит                       |
| --------------------- | ------------------------------------ |
| трижды одна позиция   | появляется **право требовать** ничью |
| пятьдесят ходов       | появляется **право требовать** ничью |
| пять раз одна позиция | ничья **сама**, без заявки           |
| семьдесят пять ходов  | ничья **сама**, без заявки           |

Право живёт, пока держится основание, и пропадает, как только позиция
изменилась. Заявить может любой из двоих.

## 8. Ход назад

`undo()` — в обычных шахматах такого нет, но у турбо-шахмат это правило
режима: «Анархия», большая красная кнопка «НЕТ» ([MODES.md](MODES.md),
режим 15). Отмотанная позиция забывается и повторением больше не считается;
кончившаяся партия не воскрешается.

## 9. Часы

Копия шахматных, про правила они не знают ничего: лимит на ход, а не бюджет
на партию. Тикают у того, чей ход, и после каждого хода счёт начинается
заново. Длительность меряется монотонными часами, а наружу дедлайн уходит
настенным временем.

## 10. Как проверено

**Сверка с `chess.js`.** На каждом узле сравниваются множество законных
ходов, запись каждого хода и недостаточный материал. Обходятся: начало партии
на три полухода, пять справочных позиций perft и особые случаи — три ферзя,
которым нужно уточнение полем, превращение со взятием и шахом, рокировка с
шахом, взятие на проходе со вскрытием, двойной шах. Сверху — восемь случайных
партий по двести полуходов с зафиксированным зерном: в них превращения,
взятие на проходе и рокировки, до которых короткое дерево не доходит.

**perft со справочными числами** (chessprogramming.org). В тестах — четыре
полухода с начала и три-четыре на справочных позициях. Один раз прогнано
глубже: пять полуходов с начала и четыре на каждой справочной — шестнадцать
миллионов позиций, всё сошлось.

**Правила через фасад** — те же сценарии, что у шахмат, плюс то, что там
закрывала библиотека: взятие на проходе и его связка, рокировка через битое
поле и из-под шаха, сгорание прав.

Скорость — около четырёхсот тысяч позиций в секунду. Боту, которому хватит
перебора на два-три полухода, этого с запасом.

## 11. Куда встанут режимы

Каждая точка расширения из [BACKLOG.md](BACKLOG.md) B4 — ровно одно место в
коде:

| Точка                     | Где в движке                                 |
| ------------------------- | -------------------------------------------- |
| расстановка               | построение начальной позиции (`position.ts`) |
| таблица ходов вида        | `PATTERNS` в `pieces.ts`                     |
| фильтр законности         | отсев в `legalMoves` (`moves.ts`)            |
| условие окончания         | `detect` в `game.ts`                         |
| при взятии и между ходами | `play` в `moves.ts`                          |
| дополнительные действия   | новые методы фасада рядом с `move`           |

Пустых заготовок под них нет намеренно. Интерфейс, который никто не зовёт,
описывает догадку, а не нужду: каждую точку выточит первый режим, которому
она понадобится.
