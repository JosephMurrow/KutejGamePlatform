# Чем проверяется правка

Три слоя, и они не заменяют друг друга. Юниты ловят логику, смоуки — то, что
живёт только на живом сервере, глаза — то, что живёт только в браузере.

## Юнит-тесты

```bash
npm test
```

225 тестов в 24 файлах на родном раннере Node (`node:test` + `node:assert`),
запускаются через `tsx`. Ни Jest, ни Vitest в проекте нет.

Плотно покрыто: машина состояний раунда, подсчёт очков со всеми спец-случаями,
очередь вопросов с детерминированным rng, короны, разбор команд Твича, разбор
IRC, фильтр гостевых ников, настроение ботов и антиповтор реплик, токены
сессии, QR (включая обратное сканирование через `jsqr` — телефон прочитает
именно ту ссылку), почтовый шаблон, ленивая env-схема.

**Отдельно стоит `src/lib/games/stub-game.test.ts`** — болванка-игра. Она
реализует интерфейс движка целиком и ничего не знает про ставки; платформа
проводит на ней партию. Это единственная проверка того, что интерфейс не
оказался формой платитутки под общим названием, и заодно первые тесты
менеджера комнат.

## Чего юниты не покрывают

`socket.ts`, `rooms.ts` (кроме болванки), мост в Твич, режиссёр ботов (кроме
`informedBet`), рейтинг, приватные комнаты, серверные экшены, компоненты.
**Правка в этих местах юнитами не ловится.** Это зона смоуков.

## Смоуки

Нужен запущенный `npm run dev` и база.

```bash
npm run smoke:sockets        # полный раунд, экран, гость, замок, реконнект
npm run smoke:crowd -- 8 2   # толпа: круг ходов и рассылка на многих
npm run smoke:chess          # партия по сокету: посадка, ходы, зритель, конец
npm run smoke:lobby 21       # общий зал: десять партий одновременно
npm run smoke:bot            # партия с ботом: движок отвечает ходом
npm run smoke:rating         # партия в зале: рейтинг, надбавка, таблица
npm run smoke:stream         # эфир: задержка для зрителей и экран по ключу
npm run smoke:magnus         # скрытый уровень: кому открыт и как жульничает
```

`smoke:sockets` проходит двенадцать разделов: скрытность вопроса в READY,
скрытность ответа ведущего, отказы чужим действиям, ставки, вскрышка, чат и
лимиты, реконнект, отказ безсессионному, вид «экран» с ключом и без, гость,
замок набора. За собой прибирает.

Полезная деталь: платитуткины смоуки **не шлют параметр игры** в сокет — то
есть заодно проверяют случай вкладки, открытой до выкладки. Шахматный, наоборот,
шлёт его всегда: без параметра сервер посадил бы за стол платитутки.

`smoke:chess` заводит комнату шахмат и проводит партию: посадка двоих и третий
зрителем, ходы и все отказы (чужой ход, чужой номер полухода, нелегальный ход,
ход от зрителя), восстановление после переподключения, сдача и уборка комнаты.
За собой прибирает.

`smoke:lobby` приводит в общий зал толпу и проверяет, что она рассаживается
парами, партии идут независимо и очередь работает. Число людей задаётся
аргументом, по умолчанию семь; нечётное — намеренно, чтобы кто-то остался
ждать.

**У каждой игры свой смоук.** Общего быть не может: платформа одинаковая, а
проверять надо именно правила и посадку, которые у игр разные.

`smoke:bot` требует движка: без `CHESS_ENGINE_PATH` у сервера бот не садится, и
смоук об этом честно говорит. Юнит-тесты движка при пустой переменной
пропускаются — в проверках его может не быть вовсе.

`smoke:magnus` проверяет и то, что уровень открыт только своему аккаунту, и то,
что он вправду жульничает: заводит две комнаты — одну открывшему, другую нет, —
и смотрит, кому какой уровень достался. Потом играет несколько ходов, берётся за
фигуру и ждёт, что соперник это прокомментирует. Отдельно проверяет, что события
про руку нет ни в одном снимке.

`smoke:stream` заводит комнату с задержкой в пятнадцать секунд и смотрит, кто
что видит: игроки и экран — сразу, зритель — только через задержку. Он же
проверяет, что снимок зрителю приходит сам, без единого действия: комната обязана
проснуться и показать созревший кадр. Прогон честно ждёт эти пятнадцать секунд —
быстрее задержку не проверить.

`smoke:rating` сажает двоих в общий зал и играет партию Морфи — тридцать три
полухода до мата. Не учебные четыре хода намеренно: надбавка за победу даётся
только в состоявшейся партии, и короткой её не проверить. Дальше он смотрит
рейтинг обоих в базе, запись партии, счётчик пар и таблицу, а потом проверяет,
что партия с ботом не меняет ничего. Именно он поймал, что в зале выигравший не
видел своей победы: доска убиралась раньше, чем итог успевал уехать в снимке.

**Смоуки заводят себе своих людей.** Комнаты и зал живут в памяти сервера, и
вернувшийся игрок садится обратно за свою недоигранную доску: прогон, взявший
тех же пользователей, мешает сам себе.

`smoke:crowd` умеет ходить на боевой через `CROWD_URL` (см.
[DEPLOY.md](./DEPLOY.md)).

## Чего не покрывают и смоуки

Кик, переименование гостя, досрочное вскрытие, рестарт партии, боты, мост в
Твич, страницы в браузере, создание комнаты формой. Всё это проверяется
руками — и проверялось: при переезде движка отдельно гонялись боты и
сгоревший раунд, при переезде настроек — создание комнаты через форму с
проверкой, что движок получил сохранённые значения, а не умолчания.

Если правка задевает что-то из этого списка — проверь руками и напиши в
отчёте, как именно.

## Предметные проверки

```bash
npm run audit:questions      # правило рода в вопросах, повторы, знак вопроса
npm run mail:check -- адрес  # живое письмо: проверяется доставкой
npm run twitch:check -- канал # связь с чатом канала
npm run bot -- Ник [код]     # бот-напарник для ручной проверки интерфейса
```

## Статика

```bash
npm run lint         # включая правило границы платформы и игры
npm run typecheck
npm run format:check
npm run build
```

`typecheck` начинается с `next typegen`. Глобальные типы маршрутов —
`LayoutProps`, `PageProps`, `RouteContext` — не пишутся руками и не лежат в
репозитории: их генерирует Next в `.next/types` при `dev`, `build` или этой
самой команде. Голый `tsc` на чистом клоне их не находил и падал с
`Cannot find name 'LayoutProps'` — генерация впереди проверки это чинит.

Всё это плюс `npm ci` гоняется на каждый пуш —
[.github/workflows/checks.yml](../.github/workflows/checks.yml). Смоуков там
нет намеренно: им нужен живой сервер и база.

## Проверка с телефона

Нужна там, где правка касается установки на домашний экран: манифест,
служебный воркер, мета-теги айфона, вид без адресной строки. С ноутбука этого
не видно вовсе.

**Всё это требует защищённого контекста.** Исключение одно — `localhost` и
`127.0.0.1`: их браузеры считают доверенными и по HTTP. Отсюда и разделение
ниже: где адрес остаётся `localhost`, ничего настраивать не надо, а где
нет — нужен настоящий сертификат.

**Флаг `next dev --experimental-https` здесь не работает.** Им это лечат
обычно, но у нас запускается не CLI Next, а `node --import tsx server.ts`
(см. [STACK.md](./STACK.md)), и прочитать флаг некому.

### Симулятор айфона — бесплатно и без туннеля

Сеть у симулятора общая с машиной, поэтому `localhost` в нём — это тот же
`npm run dev`, и защищённый контекст выдаётся сам:

```bash
xcrun simctl boot "iPhone 15 Pro"     # если ещё не запущен
open -a Simulator
xcrun simctl openurl booted "http://localhost:3000/games"
xcrun simctl io booted screenshot /tmp/sim.png
```

Проверено: витрина открывается, тема и шрифты на месте.

**Что симулятором проверяется:** добавление на домашний экран, иконка и подпись
под ней, запуск без адресной строки, поля под вырезом и полоской home,
раскладка на узком экране.

**Чего он не покажет:** заморозку свёрнутого приложения (её воспроизводит
только живое железо), настоящий обрыв связи, вид иконки среди чужих на
настоящих обоях и push-уведомления.

### Живой телефон — нужен туннель

`http://192.168.…` с телефона — уже не `localhost`, защищённого контекста нет,
и ни воркер, ни установка не заработают. Нужен настоящий домен с сертификатом:

```bash
cloudflared tunnel --url http://localhost:3000
```

Туннель ничего не трогает в проекте и живёт ровно столько, сколько открыт
терминал. В обмен он делает `npm run dev` видимым из интернета — поднимать его
стоит на время проверки, а не фоном.

Второй путь — смотреть на боевом домене: там сертификат уже есть, и это самая
честная проверка из всех, но и самая дорогая по последствиям.

### Андроид

Телефон по проводу, на машине `chrome://inspect` — дальше обычные инструменты
разработчика для страницы на телефоне. Смотреть в Application: разбор
манифеста с причинами, почему установка недоступна; состояние воркера;
содержимое кеша.

**Аудита PWA в Lighthouse больше нет** — категорию убрали, когда Chrome
перестал требовать воркер для установки. Искать её не надо.

## Порядок для правки среднего размера

1. `npm run typecheck` — быстрее всех ловит опечатки в путях.
2. `npm test`.
3. `npm run lint` и `npm run format`.
4. `npm run build` — он один ловит утечку серверного кода в браузерный бандл.
5. Смоуки, если тронуты сокеты, комнаты или движок.
6. Руками — если тронуто что-то из списка «чего не покрывают и смоуки».
